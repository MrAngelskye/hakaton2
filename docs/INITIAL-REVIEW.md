# Анализ MrAngelskye/hakaton2

Этот отчёт описывает исходный коммит до доработки. Три подтверждённые ошибки исправлены в текущем MVP; публичная часть, садики, документы и языковые версии добавлены. Текущее состояние и результаты находятся в `VALIDATION.md`.

Проверено 12 октября 2026 года. Ветка `main`, коммит `8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed`. [Исходный репозиторий](https://github.com/MrAngelskye/hakaton2).

## Главный вывод

В репозитории уже есть работающий локальный MVP: единый портал организаций, серверная база, вход и три роли. Его можно использовать как основу проекта. Для демонстрации общих страниц и разграничения доступа он подходит. Для официальных сайтов школ и детсадов нужно расширить содержание, работу с документами, языковые версии и подготовить серверное размещение.

Сейчас продукт построен как закрытый портал: без входа посетитель видит форму авторизации, а ученик или учитель — только свою организацию. Для публичных сайтов это существенное продуктовое решение, которое нужно обсудить с заказчиком. Рекомендую открывать утверждённые сведения, новости и документы всем посетителям, а редактирование оставлять в защищённых кабинетах. Если заказчик хочет именно закрытый портал, текущая модель доступа соответствует этому направлению.

Описание кейса А-2 задаёт общую платформу на сервере области и целевой масштаб около 600 организаций. Детальные разделы, языки и показатели требуется согласовать. Ниже они обозначены как рекомендации для развития, а не как уже утверждённые условия конкурса.

## Как устроен проект простыми словами

| Часть | Технология | Что делает |
| --- | --- | --- |
| Интерфейс | HTML, CSS, обычный JavaScript | Рисует страницы, формы, каталог и кабинеты |
| Сервер | Python, стандартный `http.server` | Принимает запросы, проверяет вход и разрешённые действия |
| База | SQLite | Хранит организации, новости, пользователей и сеансы |
| Начальные данные | `seed.json` | Создаёт 12 вымышленных организаций при первом запуске |
| Проверки | Python `unittest` | Проверяют действия через настоящее HTTP-соединение |
| Запуск Windows | `start-portal.cmd` | Находит Python и запускает сервер |

Это одна программа и одна база. Отдельный сайт каждой организации представляет собой страницу внутри общего интерфейса с адресом вида `#org/school-24`; отдельные домены, поддомены и независимые установки не создаются.

## Что уже реализовано

- Ученик читает свою организацию; учитель меняет её описание и публикует новости; администратор управляет организациями и пользователями.
- Права проверяются сервером при запросах. Изменение кнопки входа не превращает ученика в администратора.
- Администратор создаёт организацию, аккаунт и меняет привязку пользователя. При изменении аккаунта его существующие сеансы удаляются.
- Изменения хранятся в SQLite и доступны другим аккаунтам после обновления данных.
- Есть поиск, фильтры типов и районов, карточки, список и постраничный каталог в браузере.
- Новости можно создавать и удалять. Есть скачивание трёх видов учебных TXT-документов, формируемых сервером.
- Пароли хранятся в виде PBKDF2-хешей с отдельной солью; идентификаторы сеансов в базе тоже хешируются. Cookie содержит HttpOnly/SameSite, изменения проверяют CSRF-токен.
- Раздаются только разрешённые статические файлы; исходники, seed и база не выдаются посетителям.
- Есть мобильное меню, увеличение текста, ссылка перехода к содержимому и синхронизация входа между вкладками.

[README проекта](https://github.com/MrAngelskye/hakaton2/blob/8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed/edu-portal/README.md) и [сервер](https://github.com/MrAngelskye/hakaton2/blob/8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed/edu-portal/server.py).

## Подтверждённые ошибки

### 1. Ограничение попыток входа теряет параллельные попытки

Приоритет: исправить до размещения сервера в интернете.

Проверка: 9 последовательных ошибочных входов дают восемь ответов 401, затем 429 — ограничение работает. При 10 одновременных ошибочных входах все запросы дали 401, и следующий запрос снова дал 401. После 11 попыток счётчик содержал только 3 записи.

Причина: список попыток читается под блокировкой, затем проверяется пароль, затем сохраняется прежний список плюс одна попытка. Несколько потоков перезаписывают изменения друг друга. [server.py, строки 421–432](https://github.com/MrAngelskye/hakaton2/blob/8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed/edu-portal/server.py#L421).

Исправление: учитывать попытку атомарно до дорогостоящей проверки пароля, ограничивать число одновременных запросов и добавить отдельный тест на параллельный вход. Для нескольких серверных процессов счётчик должен быть общим. Это ослабление ограничения попыток, а не доказательство возможности войти без пароля.

### 2. Некорректный CSRF-токен обрывает соединение

Приоритет: обычное исправление устойчивости API.

Запрос с действующим учебным сеансом и не-ASCII символом в заголовке `X-CSRF-Token` вызвал `TypeError` в `hmac.compare_digest`; клиент получил обрыв соединения. Ожидается предсказуемый ответ 403 JSON. [server.py, строка 199](https://github.com/MrAngelskye/hakaton2/blob/8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed/edu-portal/server.py#L199).

Исправление: проверять допустимый формат токена перед сравнением и возвращать 403 для неподходящего значения. В воспроизведении данные не изменились и доступ к чужой организации не получен.

### 3. Дата новой новости всегда 11 октября 2026 года

Приоритет: небольшой дефект интерфейса.

В поле формы жёстко записано `value="2026-10-11"`. При открытии 12 октября показана вчерашняя дата; при последующих запусках она останется прежней. [app.js, строка 204](https://github.com/MrAngelskye/hakaton2/blob/8ead0ecd14a4d1fb14c7e34436f53bf0eecb30ed/edu-portal/dist/app.js#L204).

Исправление: подставлять текущую местную календарную дату или дату, полученную с сервера. Если нужны публикации по расписанию, отдельно добавить статус и время выпуска: сейчас выбранная будущая дата не задерживает доступность новости.

## Масштаб и технические решения

SQLite подходит для этой локальной демонстрации. Число организаций само по себе не доказывает необходимость другой базы. Проверять нужно одновременные изменения, количество новостей, время ответа и резервное восстановление.

Сейчас сервер выдаёт администратору все организации и новости, а фильтры и страницы работают в браузере. Это удобно для небольшого набора. При росте истории понадобится выдача страниц и фильтрация на сервере. Данные организаций и новостей хранятся одним JSON-текстом; для поиска, языковых версий и отчётов потребуется более явная структура и миграции базы.

Стандартный `http.server` Python [не рекомендуется для production](https://docs.python.org/3/library/http.server.html). Простое размещение текущего процесса за HTTPS не завершает подготовку к эксплуатации. Для пилота на Python разумно перенести серверную часть на поддерживаемый веб-фреймворк, например Django, сохранив полезные экраны и правила проекта. Выбор и перенос стоит делать после согласования функций, а не начинать с полной переработки интерфейса. [Контрольный список установки Django](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/) показывает типичные требования к серверной эксплуатации.

## Предлагаемая очередь работы

**Сначала — привести демонстрацию в порядок:** исправить три подтверждённые ошибки; добавить корневой README и `.gitignore` для `data/`, `__pycache__/`, локальных настроек и копий; настроить автоматический запуск тестов на GitHub. Определить, какие сведения будут публичными.

**Затем — основная ценность сайта организации:** RU/KK, реальные разрешённые PDF, нужные страницы, телефон, редактирование новости и её статус. Демонстрационный сценарий: администратор создаёт организацию, сотрудник заполняет обе версии, публикует материал, посетитель открывает его и скачивает документ.

**Перед пилотом — эксплуатация:** отдельные пароли, выключение демо, HTTPS, стабильный серверный запуск, журнал, резервная копия и реальное восстановление. Запустить 3–5 организаций и измерить время работы сотрудников.

**Перед расширением — измерения:** нагрузочные испытания на согласованном наборе материалов и посетителей, стоимость обслуживания, поддержка, обучение и регламент обновлений.

Ранее в этой рабочей папке подготовлена отдельная версия на WordPress Multisite. Она использует другую архитектуру. Копирование PHP-плагина в этот Python-проект не объединит продукты. Для команды рекомендую выбрать один основной вариант: если вы продолжаете `hakaton2`, развивать его Python-код и брать из предыдущего плана требования, сценарии и критерии приёмки.
